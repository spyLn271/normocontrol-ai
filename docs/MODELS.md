# Выбор моделей для каждой задачи

В системе несколько разных ИИ-задач, и **для каждой нужна своя модель**. Одна большая модель
«на всё» — медленно и дорого по памяти. Ниже стартовые кандидаты. **Окончательный выбор
делаем по замерам на нашем датасете** (задача 3.7 в [TASKS.md](TASKS.md)), а не по отзывам в интернете.

> ⚠️ Модели выходят каждые пару месяцев. Перед началом этапа 3 проверь, что вышло нового:
> [ollama.com/library](https://ollama.com/library), [Hugging Face](https://huggingface.co/models),
> лидерборд эмбеддингов [MTEB](https://huggingface.co/spaces/mteb/leaderboard) (смотри вкладку с русским языком).
> Если появилась модель лучше — добавь её в сравнение.

## Требования к моделям в нашем проекте

1. **Хорошо понимает русский** (и желательно казахский — документы в РК бывают на двух языках).
2. **Работает локально** через Ollama или Hugging Face.
3. **Умеет отвечать строгим JSON** (structured output).
4. **Лицензия разрешает коммерческое использование** (Apache 2.0, MIT, Llama/Gemma license — читать условия).

## 1. Основная LLM — проверка по смыслу

**Задачи:** проверка записей списка литературы, подписей к рисункам/таблицам, реквизитов,
заполненности полей шаблона, формулировок заголовков.

| Модель (Ollama) | Размер в Q4 | Плюсы | Минусы | Когда брать |
|---|---|---|---|---|
| `qwen3:8b` | ~5 ГБ | отличный русский, сильный JSON-вывод, Apache 2.0 | на слабом CPU медленно | **основной кандидат по умолчанию** |
| `qwen3:14b` | ~9 ГБ | заметно точнее на сложных случаях | нужна GPU 12+ ГБ | если хватает железа |
| `qwen3:4b` | ~2.5 ГБ | быстрый, идёт на ноутбуке | чаще ошибается | для разработки и отладки |
| `gemma3:12b` | ~8 ГБ | хороший русский, мультимодальная (видит картинки) | лицензия Gemma — прочитать | альтернатива для сравнения |
| `mistral-small` (24B) | ~14 ГБ | сильная в инструкциях | тяжёлая | если есть 24 ГБ GPU |
| `llama3.1:8b` | ~5 ГБ | популярная, много материалов | русский слабее Qwen | как baseline для сравнения |

**Про Qwen3 и «режим размышлений»:** у Qwen3 есть режим thinking (модель сначала «думает», потом отвечает).
Он повышает точность, но медленнее. Сравни оба режима в задаче 3.7. Отключается в промпте `/no_think`
или параметром API — проверь в документации Ollama.

**Казахский язык.** Для документов на казахском проверь отдельно:
- Qwen3 — неплохо понимает казахский, начни с него;
- модели от ISSAI (Назарбаев Университет), например **KazLLM**, и модель **Sherkala** — заточены
  под казахский. Ищи на Hugging Face; если нет в Ollama — запускается через GGUF-файл (`ollama create` с Modelfile).

## 2. Модель эмбеддингов — для RAG и нечёткого сравнения

**Задачи:** поиск нужного пункта ГОСТа/методички (RAG); сопоставление заголовков документа
с обязательными разделами («Список литературы» ≈ «Список использованных источников»).

| Модель | Размер | Размерность | Плюсы | Когда брать |
|---|---|---|---|---|
| `bge-m3` (BAAI) | ~1.2 ГБ | 1024 | многоязычная (рус + каз), длинные тексты до 8k токенов, есть в Ollama | **основной кандидат** |
| `qwen3-embedding` (0.6B / 4B / 8B) | 0.6–8 ГБ | до 4096 | высоко в MTEB, многоязычная | сравнить с bge-m3 |
| `multilingual-e5-large` | ~1.1 ГБ | 1024 | проверенная временем | baseline |
| `nomic-embed-text` | ~0.3 ГБ | 768 | очень лёгкая | русский заметно слабее — только если всё остальное не идёт |

Важно:
- **одной и той же моделью** делаем эмбеддинги и для базы, и для запроса. Сменил модель — переиндексируй всю базу;
- у e5-моделей нужно добавлять префиксы `query: ` и `passage: ` — без них качество падает. Читай карточку модели.

## 3. Reranker — улучшение RAG

**Задача:** из 20 найденных чанков выбрать 3–5 действительно нужных.

| Модель | Плюсы | Как запускать |
|---|---|---|
| `BAAI/bge-reranker-v2-m3` | многоязычная, пара с bge-m3 | через `sentence-transformers` (`CrossEncoder`) или `FlagEmbedding` |
| `Qwen3-Reranker` (0.6B / 4B) | свежая, сильная | Hugging Face `transformers` |

Reranker добавляем **после** того, как базовый RAG работает (задача 3.5). Сначала замеряем без него, потом с ним.

## 4. Разбор документов и OCR

| Инструмент | Для чего | Комментарий |
|---|---|---|
| `python-docx` + `lxml` | `.docx` → наша модель документа | **основной путь**, всё форматирование доступно |
| [Docling](https://github.com/docling-project/docling) (IBM) | PDF/DOCX → структурированный текст, таблицы | удобно для загрузки ГОСТов в RAG |
| `PyMuPDF` (fitz) | чтение PDF: текст, шрифты, координаты | для проверки PDF на этапе 5 |
| Tesseract (`rus`, `kaz`) | OCR сканов | если ГОСТ есть только как скан |
| Мультимодальная модель (`qwen2.5vl`, `gemma3`) | «посмотреть» на страницу как на картинку | эксперимент на будущее: проверка титульного листа визуально |

## 5. Векторная база

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| Chroma | `pip install`, без сервера, проще всего | для большой нагрузки слабее | не используем (ADR 005) |
| **Qdrant** | быстрая, фильтры по метаданным, Docker-образ; есть встроенный режим без сервера | — | **выбрано**: встроенный режим для разработки, сервер в продакшене |
| LanceDB | файл на диске, быстрая | меньше туториалов | альтернатива |
| pgvector | если уже есть PostgreSQL | настройка | если появится Postgres |

Пиши код через свой маленький интерфейс (`VectorStore` с методами `add` и `search`), тогда переход с Chroma на Qdrant — это одна новая реализация, а не переписывание проекта.

## 6. Итоговый стартовый набор

| Роль | Модель по умолчанию | Альтернатива для сравнения |
|---|---|---|
| LLM | `qwen3:8b` | `qwen3:14b`, `gemma3:12b` |
| LLM для слабого ПК / быстрых проверок | `qwen3:4b` | — |
| Эмбеддинги | `bge-m3` | `qwen3-embedding:0.6b` |
| Reranker | `bge-reranker-v2-m3` | `Qwen3-Reranker-0.6B` |
| Векторная БД | Qdrant (встроенный → сервер) | LanceDB |

Названия моделей держим **в конфиге** (`config.yaml` / переменные окружения), а не в коде:
```yaml
llm:
  provider: ollama
  model: qwen3:8b
  temperature: 0.1
embeddings:
  provider: ollama
  model: bge-m3
reranker:
  model: BAAI/bge-reranker-v2-m3
  enabled: false
vector_store:
  backend: qdrant
  url: null            # http://qdrant:6333 в продакшене
  path: data/vectors   # встроенный режим
```
Полный файл — [`config.yaml`](../config.yaml); любое значение переопределяется переменной
окружения `NC_<РАЗДЕЛ>__<КЛЮЧ>` (например `NC_LLM__MODEL=qwen3:4b`).

Первые замеры (CPU) — [ADR 004](adr/004-models-shortlist.md) и [docs/benchmarks/](benchmarks/).
Так модель можно поменять без единой правки кода. Облачную модель (например Claude) потом можно
подключить как ещё один `provider` — для сравнения качества или для клиентов, которым это разрешено.

## 7. Как правильно сравнивать модели

Подробно — задача 3.7. Коротко:
1. Берём размеченный датасет (`tests/fixtures/` + `expected_issues.json`).
2. Прогоняем проверку каждой моделью с одинаковыми промптами и `temperature: 0`.
3. Считаем precision, recall, время на документ, пиковую память.
4. Записываем результаты в `docs/benchmarks/YYYY-MM-DD-llm.md` (таблица).
5. Выбор фиксируем в ADR (`docs/adr/`).
