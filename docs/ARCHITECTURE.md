> Стек утверждён по итогам этапа A — решения, варианты и замеры в [`docs/adr/`](adr/)
> (000 — обзор, 001–006 — язык, парсинг, LLM, модели, RAG, API). Обновлено: 2026-10-25.

## Общая схема

```
 .docx ──► [1. Парсер] ──► Document Model (JSON)
                               │
              ┌────────────────┼────────────────┐
              ▼                ▼                ▼
   [2. Rule Engine]   [3. Structure Checker]  [4. LLM Checker]
   поля, шрифты,      разделы, содержание,    литература, подписи,
   интервалы, отступы нумерация рис./табл.    реквизиты, стиль
              │                │                │
              └────────────────┼────────────────┘
                               ▼
                     [5. Агрегатор] ──► Report (JSON)
                               │
                 ┌─────────────┴─────────────┐
                 ▼                           ▼
          Веб-отчёт / PDF        .docx с комментариями (позже)
```

## Компоненты

### 1. Парсер (`parser/`)
Превращает `.docx` во внутреннюю модель документа — **единый формат**, с которым работают все проверки.

- Библиотека: `python-docx` + прямое чтение XML (`lxml`) там, где python-docx не даёт данных
  (наследование стилей, колонтитулы, поля секций, нумерация).
- Важно: реальный шрифт абзаца = run → paragraph style → базовый стиль → defaults документа.
  Нужно **разрешать наследование стилей**, иначе будут ложные срабатывания.

Пример модели:
```json
{
  "sections": [{"margins_cm": {"left": 3.0, "right": 1.5, "top": 2.0, "bottom": 2.0}, "orientation": "portrait"}],
  "paragraphs": [
    {
      "id": "p-42",
      "page_estimate": 5,
      "text": "1.1 Анализ предметной области",
      "style": "Heading 2",
      "font": {"name": "Times New Roman", "size_pt": 14, "bold": true},
      "alignment": "left",
      "first_line_indent_cm": 1.25,
      "line_spacing": 1.5,
      "is_heading": true,
      "heading_level": 2
    }
  ],
  "tables": [], "images": [], "footnotes": [], "headers_footers": []
}
```

### 2. Rule Engine (`rules/`)
Детерминированные проверки по профилю. Каждое правило — маленькая функция:

```python
@rule("margins")
def check_margins(doc: Document, cfg: MarginsConfig) -> list[Issue]: ...
```

Без LLM, быстро, бесплатно, точно. **Сюда уходит всё, что можно измерить.**

### 3. Structure Checker
- обязательные разделы есть и идут в правильном порядке (с нечётким сравнением названий);
- содержание (TOC) совпадает с реальными заголовками;
- рисунки/таблицы пронумерованы подряд и на каждый есть ссылка в тексте.

### 4. LLM Checker (`llm/`)
Для того, что не формализуется жёстко:
- оформление каждой записи списка литературы по ГОСТ 7.1-2003;
- формулировки подписей к рисункам и таблицам;
- реквизиты в организационно-распорядительных документах;
- правильность заполнения полей шаблона (например, заявление: ФИО, дата, подпись на месте).

Правила работы с LLM:
- в модель отправляем **только нужный фрагмент**, а не весь документ;
- ответ — **строго по JSON-схеме** (tool use / structured output);
- каждая найденная ошибка обязана содержать `paragraph_id` и цитату — без этого отбрасываем;
  ещё отбрасываем замечания со ссылкой на правило, которого не было в промпте, с «исправлением»,
  совпадающим с исходником, и к записям, совпадающим с официальным образцом (`llm/checks.py`);
- модель не может поднять серьёзность выше заданной в профиле;
- модель: **локальная**, через Ollama (`qwen3:8b` по умолчанию) — документы не уходят во внешние сервисы. Выбор моделей — [MODELS.md](MODELS.md);
- нужный пункт стандарта модель получает через RAG — [RAG.md](RAG.md);
- все промпты лежат в `llm/prompts/` и версионируются.

### 5. Агрегатор
Сводит ошибки из всех проверок, убирает дубли, сортирует по серьёзности и месту в документе,
считает балл: `100 − Σ вес × (1 + ½·log₂(число мест))`, вес: error 8, warning 3, info 0.

Формат ошибки (общий для всех проверок, `report/model.py`):
```json
{
  "rule_id": "font.size",
  "category": "font",
  "severity": "error",
  "checker": "rule",
  "message": "Размер шрифта 12 pt в 5 абзацах (стр. 3–6), требуется 14 pt",
  "expected": "14 pt", "actual": "12 pt",
  "fix": "Выделите текст и установите нужный размер шрифта (Главная → Размер шрифта)",
  "reference": "МИ 049-2026, п. 47 (с. 13–14)",
  "reference_quote": null,
  "location": {"paragraph_ids": ["p-42", "p-43"], "pages": [3, 4, 5, 6], "section_index": null, "quote": "…"},
  "count": 5
}
```
`checker` — кто нашёл (`rule` / `structure` / `llm`), `reference` — основание (пункт документа),
`reference_quote` — цитата основания из RAG (для ИИ-проверок), `count` — сколько мест сгруппировано.

## Открытые вопросы — решения

1. **Номер страницы.** LibreOffice → PDF → сопоставление текста (`parser/pages.py`); без
   LibreOffice — метки `w:lastRenderedPageBreak` от Word, затем явные разрывы. Источник
   оценки виден в отчёте (`document.page_source`).
2. **Хранение документов.** Файл удаляется в момент начала обработки; отчёт и `.docx`
   с комментариями — 1 час (`jobs.result_ttl_s`), удаление по запросу пользователя.
3. **Конфигурация GPU.** Открыт: бенчмарк на целевом сервере (задача 3.7). На CPU (48 ядер)
   `qwen3:4b` проверяет 8 записей литературы за ~60 с, детерминированная часть — ~1 с на документ.
