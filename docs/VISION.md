# Видение продукта

## Для кого

| Сегмент | Документы | Боль |
|---|---|---|
| Студенты | курсовые, дипломы, отчёты по практике, рефераты | возвраты с нормоконтроля, дедлайны |
| Преподаватели / нормоконтролёры вузов | те же | десятки работ на ручную проверку |
| Школьники и учителя | проекты, научные работы | нет понятных инструментов |
| Сотрудники организаций и госсектора | служебные записки, приказы, письма, заявления | ошибки в реквизитах, возвраты документов |

**Рынок — только Казахстан.** Требования, шаблоны и вузы — РК; документы на казахском и русском языках.

**Путь к MVP — от лёгкого к тяжёлому:** начинаем с одностраничных документов по официальным образцам
(заявление, служебная записка), потом рефераты и отчёты, в конце — курсовые и дипломы вузов РК.
Подробно — «Лестница сложности» в [RESEARCH.md](RESEARCH.md).

## Пользовательский сценарий (MVP)

1. Пользователь открывает сайт, загружает `.docx`.
2. Выбирает тип документа и профиль требований (например «Заявление — официальный образец» или «Курсовая — вуз X»).
3. Через 10–60 секунд получает отчёт:
   - общий балл соответствия;
   - список ошибок, сгруппированных по категориям (поля, шрифты, структура, литература…);
   - для каждой — место в документе и как исправить.
4. Может скачать отчёт (PDF) или `.docx` с комментариями.

## Что входит в MVP

- [ ] Только `.docx` (PDF — позже)
- [ ] Профили для уровней 1–6 лестницы сложности (от заявления до курсовой), минимум 2 вуза РК
- [ ] Детерминированные проверки: поля, шрифт, кегль, межстрочный интервал, абзацный отступ, выравнивание, нумерация страниц
- [ ] Проверка структуры: обязательные разделы, соответствие содержания заголовкам
- [ ] LLM-проверка списка литературы и подписей к рисункам/таблицам
- [ ] Веб-страница: загрузка → отчёт

## Что НЕ входит в MVP

- регистрация, оплата, личный кабинет
- авто-исправление документа
- конструктор профилей в интерфейсе (профили пишем руками в YAML)
- проверка содержания по смыслу (антиплагиат, научная ценность) — это не нормоконтроль

## Метрики успеха

- **Точность**: ≥ 90% найденных ошибок — реальные ошибки (precision)
- **Полнота**: находим ≥ 80% ошибок, которые нашёл бы живой нормоконтролёр (recall)
- **Скорость**: отчёт по 50-страничному документу < 60 сек
- Для оценки создаём **датасет сами**: генератор документов по официальным шаблонам + известные внесённые ошибки (задача 1.2 в [TASKS.md](TASKS.md))

## Риски

| Риск | Что делаем |
|---|---|
| LLM «галлюцинирует» ошибки | всё, что можно проверить кодом, проверяем кодом; LLM отвечает строго по JSON-схеме и ссылается на конкретный фрагмент |
| У каждого вуза свои требования | профили в YAML, наследование от базового ГОСТа |
| Документы содержат персональные данные (ФИО, ИИН) | локальная модель — данные не уходят во внешние сервисы; не храним файлы после проверки; соблюдаем закон РК о персональных данных |
| Нагрузка на сервер с LLM | в модель уходят только нужные фрагменты; кэш; очередь проверок |
