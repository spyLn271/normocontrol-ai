# 001. Язык бэкенда — Python 3.12

Статус: принято (2026-10-25)

## Контекст

Нужны: чтение `.docx` с полным доступом к XML, клиенты локальных LLM, эмбеддинги, reranker,
веб-API; разработчик — начинающий.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Python** | python-docx + lxml, вся ИИ-экосистема (sentence-transformers, qdrant-client), FastAPI, pydantic | медленнее Go/.NET на CPU-задачах |
| TypeScript | один язык с фронтендом | слабые библиотеки для .docx-форматирования, бедная ИИ-экосистема |
| Go | быстрый, простой деплой | нет зрелого разбора .docx со стилями, мало ИИ-библиотек |
| C#/.NET | Open XML SDK — лучший доступ к .docx | ИИ-экосистема беднее, выше порог входа |

## Эксперимент

Разбор 400 сгенерированных документов (парсер + все правила) — 21 с вместе с генерацией,
~50 мс на документ: CPU-производительность Python не узкое место (узкое место — LLM).

## Решение

Python 3.12 (поддерживается и 3.13), менеджер — uv, линтер и форматтер — Ruff, типы — mypy
в строгом режиме, тесты — pytest. Пакет в `src/`-layout, CLI на Typer.

## Последствия

Строгая типизация (`mypy --strict`) и Ruff с широким набором правил компенсируют
динамичность языка; CI блокирует PR без зелёных проверок.
