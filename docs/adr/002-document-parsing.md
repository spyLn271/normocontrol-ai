# 002. Разбор документов

Статус: принято (2026-10-25)

## Контекст

Правилам нужно **итоговое** форматирование каждого абзаца. В `.docx` оно складывается из
docDefaults → цепочки стилей `basedOn` → нумерации → символьного стиля → прямого
форматирования, с шрифтами темы и XOR-переключателями. Без этого — ложные срабатывания.

## Варианты

| Вариант | Что даёт | Чего не даёт |
|---|---|---|
| python-docx | пакет, части, связи, удобная запись | не разрешает наследование, не видит поля, TOC-поля, темы |
| docx2python, Mammoth | текст / HTML | форматирование теряется |
| Docling | структура и таблицы для RAG | не для проверки форматирования |
| Open XML SDK / docx4j | полный доступ | другой язык |
| **python-docx + lxml + свой резолвер стилей** | всё нужное | свой код (~1000 строк с тестами) |

## Решение

* `python-docx` — открытие пакета и связей, запись комментариев (`add_comment`, с версии 1.2);
* `lxml` с безопасным парсером (без внешних сущностей и сети) — чтение XML;
* `parser/styles.py` — разрешение наследования (25 модульных тестов, в т. ч. тема, XOR,
  нумерация, `w:hanging`, кириллица в слоте `hAnsi`);
* `parser/classify.py` — роль абзаца (титульный лист, оглавление, подпись, литература…);
* номера страниц: LibreOffice headless → PDF → `pypdfium2` → сопоставление текста.
  Запасные варианты: метки `w:lastRenderedPageBreak` (Word) и явные разрывы.
* перед разбором — проверка архива (`parser/safety.py`): не-ZIP, zip-бомбы, шифрование.

**PyMuPDF не используем:** лицензия AGPL несовместима с закрытым коммерческим продуктом;
`pypdfium2` — Apache-2.0/BSD.

## Последствия

Без LibreOffice система работает, просто ошибки привязаны к абзацам (и примерно к
страницам). В Docker-образ LibreOffice входит (`WITH_LIBREOFFICE=true`, +~550 МБ).
