# Normocontrol AI

ИИ-сервис для **Казахстана**, который проверяет документ на соответствие требованиям нормоконтроля:
правилам документирования РК, официальным образцам госорганов, требованиям вузов и школ —
и выдаёт понятный отчёт «что не так, где именно и как исправить».

## Проблема

Курсовая, диплом, отчёт по практике, служебная записка, заявление в госорган —
везде есть свои правила оформления. Документ возвращают из-за неправильных полей,
не того шрифта, неверно оформленного списка литературы, пропущенного реквизита.
Проверка вручную занимает часы и у автора, и у проверяющего.

## Решение

Пользователь загружает `.docx` и выбирает профиль требований. Система возвращает:

- список нарушений с привязкой к странице / абзацу и цитатой;
- уровень серьёзности (ошибка / желательно исправить / совет);
- конкретную рекомендацию по исправлению;
- основание — пункт официального документа, на котором основано требование;
- исходный `.docx` с комментариями Word на месте каждой ошибки.

## Ключевые идеи

1. **Гибрид: код + ИИ.** Всё, что можно измерить (поля, шрифт, интервалы, отступы, структура, нумерация),
   проверяет код — точно и бесплатно. ИИ проверяет только то, что требует понимания текста (запись списка литературы).
2. **Локальная ИИ-модель.** Документы содержат персональные данные — они не уходят во внешние сервисы.
3. **RAG по официальным источникам.** ИИ не придумывает требования: он получает текст нужного пункта
   стандарта, а его замечания проходят пять проверок на «галлюцинации».
4. **Только Казахстан.** Требования, шаблоны, вузы и госорганы РК; документы на казахском и русском.
5. **От лёгкого к тяжёлому.** Сначала заявление на одну страницу, в конце — диплом.

## Быстрый старт

Нужны [uv](https://docs.astral.sh/uv/) и Python 3.12+. Для ИИ-проверок — [Ollama](https://ollama.com/).

```bash
uv sync --extra pdf                     # зависимости (+ PDF для номеров страниц и RAG)
uv run normocontrol --version

# проверка без ИИ — работает сразу
uv run normocontrol check work.docx --profile kru-mi-049-2026 --no-llm
uv run normocontrol check work.docx -p kru-mi-049-2026 --format json -o report.json --annotate work.checked.docx

# ИИ-проверки: модели и база знаний
ollama pull qwen3:8b && ollama pull bge-m3
uv run normocontrol rag index-registry research/sources.yaml   # тексты стандартов из data/standards/
uv run normocontrol check work.docx -p kru-mi-049-2026
```

Веб-интерфейс и API:

```bash
uv run normocontrol serve --reload       # http://127.0.0.1:8000/docs
cd web && pnpm install && pnpm dev        # http://localhost:3000
```

Весь стек в Docker (API, воркеры, веб, Redis, Qdrant, Ollama):

```bash
cp .env.example .env
docker compose up -d --build
docker compose --profile tools run --rm indexer      # загрузить стандарты в базу знаний
```

Развёртывание на сервере — [docs/DEPLOY.md](docs/DEPLOY.md).

## Команды CLI

| Команда | Что делает |
|---|---|
| `normocontrol check FILE -p PROFILE` | проверка; `--format json`, `-o report.json`, `--annotate out.docx`, `--llm/--no-llm`, `--fail-on error\|warning\|never` (код выхода для CI) |
| `normocontrol parse FILE -o model.json` | модель документа (шрифты с учётом наследования стилей, роли абзацев, страницы) |
| `normocontrol profiles list \| show ID \| validate` | профили требований |
| `normocontrol dataset generate --count 100` | документы с известными ошибками + `expected_issues` |
| `normocontrol eval DIR --out docs/benchmarks/…` | precision / recall по каждому правилу |
| `normocontrol rag index FILE \| index-registry \| search \| eval \| stats` | база знаний по стандартам |
| `normocontrol serve` / `normocontrol worker` | HTTP API / воркер очереди (arq + Redis) |

## API

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/checks` | загрузить `.docx` (`file`, `profile_id`, `annotate`, `use_llm`) → `202` |
| `GET` | `/api/checks/{id}` | статус по шагам и отчёт |
| `GET` | `/api/checks/{id}/annotated.docx` | документ с комментариями |
| `DELETE` | `/api/checks/{id}` | удалить результаты досрочно |
| `GET` | `/api/profiles`, `/api/profiles/{id}` | профили |
| `GET` | `/healthz`, `/readyz`, `/metrics` | здоровье и метрики Prometheus |

Ошибки — в едином формате `{"error": {"code": "...", "message": "..."}}`. Полная схема — `/docs` (OpenAPI).

## Структура репозитория

```
├── profiles/                 # YAML-профили требований
├── research/sources.yaml     # реестр источников (файлы — в data/, не в git)
├── src/normocontrol/
│   ├── parser/               # .docx → модель документа (стили, роли абзацев, страницы)
│   ├── profiles/             # схема профиля, загрузка, extends
│   ├── rules/                # Rule Engine: страница, текст, заголовки, реквизиты, даты
│   ├── structure/            # разделы, содержание, рисунки/таблицы, список литературы
│   ├── llm/                  # клиенты Ollama / OpenAI-совместимые, промпты, ИИ-проверки
│   ├── rag/                  # извлечение, чанкинг по пунктам, эмбеддинги, Qdrant, поиск
│   ├── report/               # агрегатор, балл, консоль, .docx с комментариями
│   ├── dataset/              # генератор документов и мутации (известные ошибки)
│   ├── evaluation/           # precision / recall
│   ├── api/                  # FastAPI, очередь arq, воркер, метрики
│   ├── pipeline.py           # конвейер проверки
│   └── cli.py
├── tests/                    # pytest: модульные, сквозные по мутациям, API, Redis/arq
├── web/                      # Next.js: загрузка → прогресс → отчёт
├── docs/                     # документация, ADR, бенчмарки
├── Dockerfile, docker-compose.yml, .github/workflows/ci.yml
```

## Данные и приватность

Загруженный документ хранится только до начала обработки, отчёт — 1 час (настраивается), Redis без записи на диск,
тексты документов не пишутся в логи. Тексты стандартов и реальные документы в репозиторий не попадают (`data/` в `.gitignore`).
